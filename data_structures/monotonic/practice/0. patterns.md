# Monotonic Stack and Queue Patterns Cheat Sheet

## Pattern: Monotonic Stack

**Use when:** Each element needs its nearest greater or smaller neighbor, or must act as a boundary.

**Pattern:** Pop dominated candidates before pushing the current index.

**Key insight:** A popped element has found the first future value that resolves it and never needs consideration again.

### Key skills

- Store indices when distance or width matters
- Choose increasing versus decreasing order
- Use sentinels to flush unresolved candidates

## Pattern: Monotonic Deque Window

**Use when:** A moving range needs its minimum, maximum, or best undominated candidate.

**Pattern:** Remove expired indices from the front and dominated values from the back.

**Key insight:** The front is always the best valid candidate in $O(1)$ amortized time.

### Key skills

- Store indices to detect expiration
- Maintain separate minimum and maximum deques when needed
- Combine prefix sums with a deque for negative-number ranges
