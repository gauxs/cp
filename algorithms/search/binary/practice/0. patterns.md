# Binary Search Patterns Cheat Sheet

## Pattern: Standard Binary Search on Sorted Array

**Use when:** The search space is indices in a sorted array (find target, insert position, boundary of a value).

**Pattern:** Binary search on index range `[low, high]` with direct comparison against `arr[mid]`.

**Key insight:** Sorted order lets you eliminate half the index space each step.

### Key skills

- boundary initialization (include all valid indices)
- mid calculation without overflow
- left vs right mid paired with correct shrink logic
- avoiding infinite loops when only two elements remain

## Pattern: Binary Search on Answer

**Use when:** The answer is a value in a range (not an index), and a monotonic `check(mid)` or `count(mid)` exists - optimization, feasibility, or kth-element problems.

**Pattern:** Binary search on the answer domain; pick candidate `mid`, validate with a helper, shrink based on monotonicity.

**Key insight:** If `check(k)` is monotonic (true for all larger k, or false for all larger k), the answer lies in a contiguous value range - binary search applies even when there is no sorted array to index.

### Key skills

- spotting monotonicity in the answer domain (not just in input data)
- setting `low`/`high` to the full possible answer range
- writing `check(mid)` - greedy feasibility (ship packages, split array, eat bananas)
- writing `count(mid)` - how many values ≤ mid (kth smallest, multiplication table)
- matrix counting - walk sorted rows/columns to count ≤ mid in O(n)
- pair counting - sorted array + two pointers / sliding window for distance ≤ mid
- inclusion-exclusion counting (Ugly Number III)
